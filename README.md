# Parts List Selector

選択した装置仕様とPL選定条件を照合し、固定された各ユニットに適合するParts List（PL）を抽出する、PC向けの日本語Webアプリです。独自のバックエンドを使わず、マスターデータはブラウザのIndexedDBへ保存し、必要に応じてGoogle Driveへバックアップできます。

## 起動方法

Node.js 20以降を用意し、次のコマンドを実行します。

```bash
npm install
npm run dev
```

表示されたURLをブラウザで開いてください。本番用ファイルは `npm run build` で `dist/` に生成できます。テストは `npm test` で実行します。

## 操作方法

1. 「仕様選択・結果」の「仕様選択」タブで各仕様を選択します。未選択のままでも実行できます。
2. 「PL選定結果」タブは初期状態から利用できます。タブを直接クリックすると、その時点の選択仕様で判定して結果を表示します。「PLを選定」ボタンからも同じ結果タブへ切り替えられます。
3. 結果タブから仕様タブへ戻って条件を変更し、何度でも再選定できます。ユニット名または行をクリックすると、全PLと条件ごとの一致・不一致・未選択を確認できます。
4. 複数候補の場合は詳細画面の「このPLを選択」で明示的に確定します。
5. 検索欄ではユニット名、PL品番、備考を絞り込めます。「CSV出力」で結果を保存できます。

PCでの一覧確認を優先し、本文・表・タブ・条件タグ・操作ボタンは14px以上を基準に表示します。補助的なコードや件数も11～13pxを確保しています。

## CSVのデータ形式

CSVはUTF-8（出力時はExcelで判別しやすいBOM付き）です。値にカンマ、改行、引用符を含むCSVにも対応します。画面から一度CSV出力し、そのファイルを編集して取り込む方法を推奨します。

### 仕様項目マスター

| 列 | 内容 |
|---|---|
| 仕様No. | 表示順と対応する1～66の番号 |
| 仕様コード | 条件で参照する `S001`～`S066` の一意のコード |
| 仕様項目名 | 画面の表示名 |
| 選択肢（\|区切り） | `S001-1=SRC350-M2-3X-F` の形式で記載するプルダウン候補 |
| 表示順 | 数値（昇順） |
| 参照 | MW01などの従来資料上の参照コード |
| 備考 | 選択時の判断基準。仕様選択画面でプルダウンの右側に表示 |

仕様と選択肢は名称ではなくコードで関連付けます。たとえばNo.1「型式」の1番目「SRC350-M2-3X-F」は `S001-1`、No.2「Cleaning veh. CE対応」の1番目「必要」は `S002-1` です。プルダウンではコードと表示名を併記しますが、選択・判定・保存にはコードを使用します。

仕様選択時の判断に必要な備考は66項目すべてマスターで管理し、各プルダウンの右側へ表示します。「備考」の見出しは一覧上部に一度だけ表示し、各行では読みやすい大きさの本文だけを表示します。画面幅が狭い場合は、備考をプルダウンの下へ移動します。

### ユニットマスター

`ユニットNo., ユニット名, 表示順, 備考` の順です。ユニットNo.はPL選定条件のユニットNo.と一致させます。

### PL選定条件マスター

先頭5列は `ユニットNo., PL品番, PL名称, 備考, 選定対象` です。6列目以降のヘッダーには仕様コード（`S001`～`S066`）を記載し、各セルには適合する選択肢コード（例: `S001-1`）を設定します。複数の値を許容する場合は `S001-1|S001-2` のように記載します。空欄は判定対象外です。同じユニット内のPL品番は必ず一意とし、廃番・統合品は「選定対象」を `0` にします。

管理画面ではPL条件をユニットごとのタブに分けます。タブを開くと、そのユニットの判定に使う現在の選択仕様をモニター表示し、すべての条件が一致したPLを緑色で強調します。モニターの仕様カードをクリックすると仕様選択タブへ切り替わり、該当するプルダウンまでスクロールしてフォーカスします。

初期確認用ファイルは [`public/samples/specifications.csv`](public/samples/specifications.csv)、[`public/samples/units.csv`](public/samples/units.csv)、[`public/samples/rules.csv`](public/samples/rules.csv) にあります。

## PL選定ルール

- PLに設定された空欄でない条件が、選択仕様と**すべて一致**した場合のみ候補とします。
- 条件が空欄の仕様項目は判定対象外です。
- 1件一致は「選定済み」、0件は「候補なし」、2件以上は「複数候補あり」です。
- 複数候補を自動確定しません。詳細画面からユーザーが選択します。
- 候補になり得るPLの条件に必要な仕様が未選択の場合、不足項目を結果に表示します。
- 選定ロジックはUIから分離した `src/services/selector.ts` にあります。

## 選定対象ユニット

ユニットマスターの表示順に従って選定します。初期データには、提示されたNo.100「DRIVE GEAR BOX (350X)」からNo.720「LOGO STICKER(客先)」までを登録しています。提示された表を数えると27件のため、初期データも27件です。28件目がある場合はユニットNo.と名称をユニットマスターCSVへ追加してください。

## IndexedDBの保存内容

- データベース名: `parts-list-selector`
- バージョン: `7`（ユニークPL・複数許容条件・ユニットタブ対応）
- オブジェクトストア: `master`
- 保存内容: 仕様項目、ユニット、PL選定条件の3マスター

保存処理は `src/services/storage.ts` に分離しています。旧データ構造との互換性を保てないマスター更新ではデータベースバージョンを更新し、初回アップグレード時に新しい初期マスターを登録します。重要な登録内容は更新前にCSVまたはGoogle Driveへ保存してください。仕様の選択内容と選定結果は一時的な画面状態であり、永続保存しません。

## Google Driveへの保存

Google Drive連携は任意です。利用する場合はGoogle Cloud Consoleで次の準備を行います。

1. プロジェクトで **Google Drive API** を有効にします。
2. OAuth同意画面を設定し、「ウェブ アプリケーション」のOAuth 2.0クライアントIDを作成します。
3. クライアントの「承認済みのJavaScript生成元」へ、アプリを開くURL（例: `http://localhost:5173`）を登録します。
4. マスターデータ管理画面の「Google Drive保存」にクライアントIDを入力して接続します。
5. 「現在のマスターを保存」でバックアップし、「Driveから読み込む」でIndexedDBへ復元できます。

Google Driveには `PartsListSelector-master.json` というファイルを作成し、3種類のマスターをまとめて保存します。OAuthスコープは `drive.file` のため、このアプリが作成したファイルだけにアクセスします。アクセストークンはメモリ内だけに保持し、画面を閉じると破棄します。クライアントIDは秘密情報ではなく、入力の手間を省くためブラウザのLocal Storageへ保存します。

## マスターデータの追加・更新方法

1. 「マスターデータ管理」を開きます。
2. 対象マスターのカードまたは「内容を表示」を押すと、現在の登録内容を表で確認・検索できます。
3. 対象マスターを「CSV出力」します。
4. 表計算ソフト等で行を追加・修正します。仕様No.およびユニットNo.の対応関係を維持してください。
5. 対象カードの「CSV取込」を押し、更新ファイルを選択します。

取り込みは対象マスターを**全件置換**し、即座にIndexedDBへ保存します。「サンプルに戻す」で全マスターを初期データに戻せます。重要なデータは更新前にCSV出力してバックアップしてください。
